# DATA_FORMATS.md

## Timing unit: beats, not seconds

`NoteEvent.startTime`/`duration`, `ChordEvent.startTime`/`duration`, and
`SongSection.startTime`/`endTime` are all in **beats** (quarter notes) from
the start of the song — not seconds, not milliseconds, not MIDI ticks.

Why: this matches how MIDI/MusicXML/piano-roll software actually represents
musical time, keeps harmony-core's math independent of BPM (a chord
progression and its melody don't change shape if you speed the song up),
and is what makes chord-grid alignment (`findActiveChord` in `planner.ts`)
simple integer/float comparison instead of a tempo-aware conversion at
every step.

Conversion only happens at the edges:
- MIDI export: `beatsToTicks(beats) = round(beats * TICKS_PER_BEAT)`,
  `TICKS_PER_BEAT = 480` (`midi-export.ts`).
- Playback (Phase 3, not built yet): will need `secondsPerBeat = 60 / bpm`.

This project assumes a constant BPM for the whole song in the MVP (Phase
1-2). Tempo changes mid-song are out of scope until explicitly revisited —
if you add them, `beatsToTicks` and any playback code both need a tempo
map, not a single BPM.

## Core types (`packages/shared-types/src/*.ts`)

All are zod schemas with an inferred TS type of the same name (lowercase
`xSchema` exports the schema, `X` exports the type). Validate any data
crossing a trust boundary (file import, IndexedDB read) with the schema —
don't just cast.

- `NoteEvent` — one melody note. `source` tracks provenance
  (`user-input`/`midi-import`/`musicxml-import`/`pitch-detection`/`generated`);
  `confidence` is 1.0 for anything hand-entered/imported, and must be a real
  number for detected data — never a placeholder.
- `ChordEvent` — `root` (pitch class string) + `quality` (enum) +
  `extensions` (free-form strings like `"9"`, `"b13"`) + optional `bass`
  for slash chords.
- `SongSection` — `type` (intro/verse/preChorus/chorus/postChorus/bridge/
  breakdown/finalChorus/outro/custom) + `energy` + `harmonyDensity`
  (0-1, target proportion of notes that get harmonized).
- `VocalRange` — hard `lowestPitch`/`highestPitch` plus a `comfortableLow`/
  `comfortableHigh` band nested inside it. `DEFAULT_VOCAL_RANGE` is a
  reasonable mid-range default, not tied to any specific voice type.
- `HarmonyNote` — one generated second-vocal note, always linked back to
  `originalNoteId`. `generatedPitch: null` means a rest.
  `scoreBreakdown: Record<string, number>` is the real per-component scores
  from `docs/HARMONY_RULES.md` §3, not a summary/decoration.
- `ArrangementInstruction` — the section-level plan flags (see
  `HARMONY_RULES.md` §4). It's a flat object of booleans, not an enum,
  because real plans combine more than one idea at once.
- `DuetArrangement` — one full generation run's output: unchanged
  `sourceMelody`, `harmonyTrack`, `sectionPlans`, `style`, aggregate
  `overallScore`/`scoreBreakdown`, `warnings`, and `generationVersion` +
  `randomSeed` for reproducibility/debugging.

## Project file format (`packages/shared-types/src/project.ts`)

```json
{
  "schemaVersion": "1.0.0",
  "id": "...", "name": "...", "createdAt": "...", "updatedAt": "...",
  "bpm": 96, "key": "C major",
  "mainMelody": [...], "chords": [...], "sections": [...],
  "vocalRange": {...},
  "arrangements": [...]
}
```

`CURRENT_SCHEMA_VERSION = "1.0.0"`. `migrateProjectFile(raw: unknown)`
validates `schemaVersion` first, then dispatches to the matching schema; it
throws `UnsupportedSchemaVersionError` for anything else. **When you add a
v2**: define `projectFileSchemaV2`, keep `projectFileSchemaV1` (old exported
files must stay loadable), and add a `case "1.0.0":` branch that upgrades a
v1 object to v2 shape before returning it — don't just widen the union and
call it done, actually write the upgrade logic.

## Example fixtures

`examples/demo-projects/*.json` are real `ProjectFile` records generated by
`packages/harmony-core/scripts/generate-examples.ts` — they validate
against `projectFileSchema` (the script calls `migrateProjectFile` on its
own output before writing, so an invalid fixture can't be committed by
accident).
